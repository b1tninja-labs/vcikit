# SAE J2534-1 — the spec gap, and how the backend is grounded

The J2534 backend (`vcikit-j2534`) drives a registered SAE J2534-1 v04.04 pass-through DLL for ISO
15765. Its API — `PassThruOpen` / `Connect` / `StartMsgFilter` / `WriteMsgs` / `ReadMsgs` /
`Disconnect` / `Close`, the `PASSTHRU_MSG` struct, the protocol/flag/status constants — comes from
the SAE J2534-1 standard.

## The gap

**SAE J2534-1 is not in `primarysource`.** The SAE local collection is behind the owner's
`PRIMARYSOURCE_SAE_ACCEPT_TERMS` gate on an unmerged branch, so the `sae_*` tools cannot be used to
cite `sae:j2534@2002` today (confirmed 2026-11-22). This crate therefore does **not** cite J2534-1
clause by clause. Its constants and struct layout are grounded in:

1. **Public J2534-1 v04.04 knowledge** — the function set, the `PASSTHRU_MSG` field order, and the
   constant values (`ISO15765 = 6`, `ISO15765_FRAME_PAD = 0x40`, `CAN_29BIT_ID = 0x0100`,
   `FLOW_CONTROL_FILTER = 3`, the status codes) are the stable, widely-published v04.04 API.
2. **Cross-check against the recovered native pass-through.** The owner's registered VXDIAG
   pass-through `VCXPT32.dll` was reverse-engineered statically (session notes
   `vcx-open-row-recovered-from-vcxpt32.md`): for ISO 15765 it copies `PASSTHRU_MSG.Data` verbatim,
   and that `Data` is `[4-byte big-endian CAN id][application PDU]` on both send and receive. The
   bring-up it performs is `Open → Connect(baud/flags) → StartMsgFilter(flow control) →
   WriteMsgs/ReadMsgs`. The backend reproduces exactly that sequence.
3. **ISO 22900-2:2009, which *is* in `primarysource`.** It confirms the raw-mode CAN-id convention
   independently (`iso:22900-2@2009` §9.2.6.3.6 request, §11.1.4.18.5 response) and maps the D-PDU
   API to SAE J2534-1 one-to-one (Annex A, Table A.1: `PassThruConnect` ↔ `PDUConnect`,
   `PassThruWriteMsgs` ↔ raw-mode `PDUStartComPrimitive`, …). See `docs/iso-map.md`.

## When the gate opens

When the owner merges the SAE collection and accepts the terms, replace this file's "public
knowledge" grounding with direct `sae:j2534@2002` citations (the function prototypes in §7, the
`PASSTHRU_MSG` definition, the `Connect`/filter flags, and the Appendix A protocol/pin tables), and
mark each constant in `src/j2534.rs` with its clause. Until then, treat the J2534 constants as
**documented but not primary-source-verified**, exactly as `gmdtcdb` marks the SAE J2012 DTC packing.

## J2534-2 and RP1210a

No J2534-2 document is known to be in the owner's files. RP1210a is named by ISO 22900-2 Annex A as a
third raw-mode consumer but is out of scope — this backend targets J2534-1 ISO 15765 only.
